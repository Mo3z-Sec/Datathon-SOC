# CyberShield AI — Integration Guide

Hospital SOC that fuses network detection, log anomaly detection, and threat
intelligence into one criticality-weighted **risk score**, shown in a dashboard,
running on **IBM LinuxONE**.

This file explains how everyone's separate part connects. The technical rules live
in [`shared/CONTRACT.md`](shared/CONTRACT.md).

## The pipe

```
[data_pipeline]  Nour  : clean data + scaler + asset table + threat intel
        │
        ▼
[models]         Hanan : network_score  (is this flow an attack?)
[models]         Bardia : anomaly_score (is this log unusual?)
[data_pipeline]  Nour  : threat_flag    (is the indicator known-bad?)
        │
        ▼
[engine]         Jason : risk_score + recommended_action
        │                (fuses the three, weighted by asset criticality)
        ▼
[dashboard]      Felix : Streamlit front-end (reads the alert table only)
        │
        ▼
[deploy]         Moe   : Docker + LinuxONE run + response simulation
```

## Repo layout

| folder | owner | what goes here |
|---|---|---|
| `data_pipeline/` | Nour | dataset cleaning, splitting, privacy, assets, threat intel |
| `models/` | Hanan, Bardia | trained models + `model_features_*.json` + `score()` entry points |
| `engine/` | Jason | real-time loop, risk fusion, writes `engine/alerts.csv` |
| `dashboard/` | Felix | Streamlit app reading the alert table |
| `deploy/` | Moe | Dockerfiles, LinuxONE run scripts, response sim |
| `shared/` | everyone | the contract, schema helper, asset table, sample alerts |

## The shared table

Everyone produces/consumes the same 9 columns (see `shared/CONTRACT.md`):

```
timestamp, asset, criticality, src_ip_hashed, network_score,
anomaly_score, threat_flag, risk_score, recommended_action
```

- `shared/sample_alerts.csv` is a ready-made example (generated by
  `shared/make_sample_alerts.py`) — Felix can build the dashboard against it **today**.
- `shared/schema.py` has `compute_risk_score()`, `recommended_action()` and
  `validate_alert_row()` so nobody re-implements the math differently.

## Quick start

```powershell
# 1. data (Nour)
cd data_pipeline; python download_data.py; python pipeline.py; python privacy.py; python accuracy_test.py; python threat_intel.py

# 2. contract demo (anyone)
python shared/make_sample_alerts.py     # (re)writes shared/sample_alerts.csv
python shared/schema.py                 # prints a validated example row
```

## Rules so parts don't collide

1. Stay in your own folder; only touch `shared/` by agreement.
2. Only **Jason** writes `risk_score` / `recommended_action`.
3. Missing values are `0.0` (scores) or `0` (flags) — never blank.
4. Never commit secrets (`secret.key`) or raw `data/`.
5. Hospital rule: response isolates, never shuts down clinical systems.

## LinuxONE

The whole system must run on IBM LinuxONE (`s390x`). See `data_pipeline/run_on_linuxone.sh`
for Nour's part, and `deploy/README.md` for Moe's container plan.
