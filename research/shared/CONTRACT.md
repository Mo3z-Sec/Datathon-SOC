# CyberShield AI — Integration Contract (v1)

This is the single source of truth for how every teammate's part connects.
If your code reads or writes an alert, it **must** use these exact column names.
Anything not in this file is "internal" to your own folder and free to change.

---

## The one table everyone shares: an alert row

Every detection flow that matters becomes exactly one row with these columns, in this order:

| column | type | range | who produces it | meaning |
|---|---|---|---|---|
| `timestamp` | string (ISO-8601 UTC) | — | Jason (engine) | when the event fired |
| `asset` | string | one of `shared/assets.csv` | Nour (pipeline) | which hospital system is involved |
| `criticality` | int | 1–5 | Nour (pipeline) | how important that asset is (5 = most critical) |
| `src_ip_hashed` | string | 12 hex chars | Nour (privacy) | privacy-safe repeatable ID of the source |
| `network_score` | float | 0.0–1.0 | Hanan (model) | "this network flow looks like an attack" |
| `anomaly_score` | float | 0.0–1.0 | Bardia (model) | "this log looks unusual" |
| `threat_flag` | int | 0 / 1 | Nour (`is_known_bad`) | source/IP/URL is on a known-bad list |
| `risk_score` | float | 0.0–1.0 | Jason (engine) | fused, criticality-weighted final risk |
| `recommended_action` | string | see below | Jason (engine) | what the SOC should do |

Sample rows live in `shared/sample_alerts.csv` (generated by `shared/make_sample_alerts.py`).

---

## Score definitions (keep them 0.0–1.0)

- **`network_score`** — Hanan's classifier `predict_proba` for the "attack" class.
- **`anomaly_score`** — Bardia's anomaly model, normalized so 0 = normal, 1 = very anomalous.
- **`threat_flag`** — `1` if the indicator is on OpenPhish/URLhaus (or any feed), else `0`.

If a model cannot produce a score for a row, use `0.0` (not empty) so the fusion never breaks.

---

## Risk fusion (Jason implements this; it is a proposal, tune if needed)

```
base       = 0.6*network_score + 0.3*anomaly_score + 0.1*threat_flag
weight     = 0.7 + 0.1*criticality          # criticality 1 -> 0.8, 5 -> 1.2
risk_score = min(1.0, round(base * weight, 3))
```

Why: the same attack against an **EHR Server (5)** must outrank the same attack against **Guest Wi-Fi (1)**.

## Recommended actions (thresholds)

| risk_score | recommended_action |
|---|---|
| `>= 0.80` | `Isolate affected subnet; keep clinical systems running; escalate to on-call.` |
| `0.50 – 0.79` | `Block source and alert the analyst.` |
| `< 0.50` | `Monitor and log.` |

For a hospital, response must **never** take down clinical systems — isolate, don't shut down.

## Handoff points (what each person gives the next)

1. **Nour → everyone:** split CSVs (`data_pipeline/outputs/*.csv`), `scaler_*.json`,
   `encoders_unsw.json`, `shared/assets.csv`, `threat_intel.is_known_bad(url)`.
2. **Hanan → Jason:** a saved model + `model_features_unsw.json` (the exact feature order),
   and a `score(flow) -> float` entry point.
3. **Bardia → Jason:** a saved anomaly model + `score(log) -> float`.
4. **Jason → Felix:** a stream/table written in the schema above (`engine/alerts.csv` for the demo).
5. **Felix → judges:** Streamlit dashboard that only reads the alert table.
6. **Moe → team:** LinuxONE environment, containers, and the response simulation.

Rule of thumb: **only Jason writes `risk_score` and `recommended_action`.** Everyone else fills their own column.
